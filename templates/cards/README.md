# Формы карточек v1

Мастер скачивает актуальные XLSX и DOCX во вкладке «Импорт» игрового стола.
Генератор — `backend/app/card_import/templates.py`; бинарные копии в репозитории
не хранятся, чтобы скачать всегда ту версию, которую читает приложение.
Примеры «Страж» и «Факел» демонстрационные: замените их своими данными.

JSON — канонический формат. Минимальный набор показан в `example-v1.json`.
Поддерживаются полный экспорт одной Card и `{schema_version, cards}`.
Идентификаторы записей из экспорта не переиспользуются: каждый подтверждённый
экземпляр получает независимые ID карточки, предметов инвентаря, способностей и
опционального токена. `external_key` связывает листы и повторные черновики, а не
объединяет итоговые карточки. Не меняйте ключ между версиями одного документа.

## Совместимый контракт v0 → v1

v1 вводится впервые. v0 — явно заданный совместимый входной контракт, **не
исторически выпущенная версия**. Структура совпадает с v1; отсутствующие
`count`, `create_token` и `external_key` получают соответственно 1, false и
детерминированный `entity-N` в порядке документа. Старые и отсутствующие
card-level версии нормализуются в 1; итог всегда DraftSet v1 с диагностикой
`migrated_v0`. Версии кроме 0 и 1 отклоняются. Тот же контракт версии применим
к XLSX (Инструкция!A1=`schema_version`, B1=0/1) и размеченному DOCX/TXT/PDF.
Legacy HTML не является версией этого шаблона.

## Заполнение

- XLSX: лист «Карточки» задаёт внешний ключ, название, тип и количество;
  «Ресурсы», «Навыки», «Инвентарь», «Способности», «Токены», «Поля» связываются
  тем же внешним ключом. Незнакомые столбцы сохраняются как дополнительные поля
  с предупреждением; незнакомые листы отклоняются, их данные перенесите в «Поля».
- DOCX: повторяйте раздел «Карточка: ключ» и таблицу из двух столбцов.
  TXT и извлекаемый текст PDF используют строки `Поле: значение`:
  `schema_version: 1`, `Карточка: guard`, `Название: Страж`.
  Произвольная проза и скан PDF без текста не распознаются; OCR/AI отсутствуют.
- Ресурс: `ключ | название | текущее | максимум`; способность:
  `название | действие | описание`. Неизвестные подписанные поля сохраняются.
- Видимость: «Всем», «Только мастеру», «Владельцу»; тип:
  «Персонаж», «NPC», «Моб», «Объект»; создать токен: «Да» / «Нет».
- Формулы, макросы, активные вложения, внешние связи и XML DTD запрещены.

До подтверждения проверьте каждый черновик, исправьте карточку, исключите лишние
и задайте количество. Повторный файл требует выбора: обновить открытые черновики
по ключам или создать новый набор. Завершённые карточки не перезаписываются.
Исходник удаляется после подтверждения/отмены или истечения 24 часов (очистка
раз в минуту при работающем API). Черновик доступен только создавшему его мастеру.

## Локальный Old Russia → JSON v1

Из корня свежего клона репозитория, с уже установленными зависимостями проекта:

```sh
PYTHONPATH=backend .venv/bin/python scripts/old_russia_export.py \
  --cards-root /absolute/path/to/cards --output-dir /absolute/path/to/export
```

`cards-root` задаётся явно; родительская папка не ищется автоматически. Bridge
читает `index.html` и пять исходных hero HTML без исполнения JS/HTML. Его runtime:
Python 3.13–3.14, стандартная библиотека и существующий Pydantic/пакет VTT.
Новых зависимостей нет. Для тестов клиентского скачивания используется уже
закреплённый frontend dev runtime jsdom; Node нужен для старого генератора.
Фикстура реального корпуса хранится в `tests/card_import/fixtures/old_russia_corpus_v1.json`;
тесты свежего клона не обращаются к чужому `../cards`.

Результат — `old-russia-v1.json` из 22 карточек и 22 отдельных JSON: пять
`player_character`, девять `npc`, восемь `mob`. `external_key=old-russia:<source-id>`
и вложенные UUID детерминированы. Сервер при подтверждении создаёт новые ID.
Свойства overview становятся подписанными `fields`; здоровье — `resources`,
спасброски — `skills`, оружие/вещи — `inventory`, умения/ульта/действия — `abilities`.
Исходные формулировки действий overview сохраняются отдельно от подробных умений.
Характеристики, модификаторы, роль, сцены, сигил и особенности сохраняются в полях;
преимущества, подсказки и история — в `notes`. Числа из прозы не превращаются
в количество предметов или геометрию; автоматизации правил нет.

Чтобы добавить кнопки к локальному корпусу, сначала сохраните резервную копию,
проверьте целевую папку, затем выполните ту же команду с `--apply`:

```sh
PYTHONPATH=backend .venv/bin/python scripts/old_russia_export.py \
  --cards-root /absolute/path/to/cards --apply
node /absolute/path/to/cards/build_old_russia_pages.js
```

`--apply` изменяет только builder, оба каталога `index.html`, 22 generated HTML
и локальный `old_russia_export_client.js`. Пять корневых hero HTML сохраняются.
Повторное применение даёт те же байты. До первой записи проверяются все целевые
leaf/ancestor пути; символьные ссылки отклоняются. Builder проверяет границы и
отпечатки источников до генерации страниц, затем запускает локальный Node installer
из asset: повторная генерация возвращает кнопки без Python и без путей к клону.
Если overview/исходный герой изменились, preflight явно отклоняет устаревший
пакет до перезаписи существующих страниц: повторите bridge и `--apply` перед генерацией. Asset содержит данные
и работает с `file://` без аккаунта, сервера или внешних шрифтов.

На overview доступны отдельный JSON каждой видимой карточки и весь пакет.
В generated каталоге можно выбрать карточку и скачать отдельный JSON или весь
пакет; на каждой из 22 страниц доступны обе кнопки. Скачивание открытой страницы
отражает её HP (в том числе 0), proficiency и spent pips. Overview берёт HP
только видимых в данный момент карточек; скрытые фильтром и другие страницы
используют исходные значения. Межстраничной синхронизации нет. Некорректное
видимое состояние останавливает скачивание с сообщением. Auth, скрипты и
произвольные ключи localStorage не включаются. JSON загружается в обычный
нативный «Импорт»: проверьте/отредактируйте черновики и явно подтвердите.
