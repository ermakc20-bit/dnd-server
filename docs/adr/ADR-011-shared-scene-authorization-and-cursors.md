# ADR-011 — Shared-scene authorization and event cursors

## Контекст

Общая кампания может содержать сцену, доступную из нескольких комнат, при этом права участников и игровые команды остаются привязаны к их комнате. Realtime-команда и доставка должны учитывать истечение зарегистрированной сессии и отражать одно изменение сцены согласованно во всех затронутых комнатах.

## Решение

Сервер проверяет действительность зарегистрированной сессии при потреблении realtime-билета, доставке сокета и повторно после блокировки комнаты перед фиксацией команды. Изменение общей сцены создаёт одно исходное событие и receipt; сервер согласованно обновляет версии затронутых комнат и выдаёт каждому получателю разрешённые курсоры и сигналы пробуждения через HTTP и WebSocket. Авторизация участника и карточки остаётся локальной для комнаты.

## Почему

Проверка срока только при подключении оставляет окно для команды или закрытых данных после истечения JWT. Отдельные исходные события на каждую комнату расходятся по receipt и происхождению изменения. Повторная серверная проекция сохраняет видимость и права каждого получателя без передачи сырых игровых событий.

## Последствия

Истечение сессии учитывается на границе выполнения и доставки, а общее изменение имеет единое происхождение при согласованных версиях и уведомлениях комнат. Реализация не требует менять схему данных для принятого сценария. Эта гарантия относится к проверяемому локальному контуру и не подтверждает работу hosted-провайдера или WAN.
