## Исправленные проверки

- Realtime-тесты открывают панель «Сцена» и используют доступные индикаторы связи/содержимое снимка вместо убранного из дизайна номера версии. Сохранены проверки read-only, автоматического восстановления, запрета команд до полного sync и очистки при отзыве доступа.
- Интеграционные тесты работают с явно заданными локальными портами. Подключения, создаваемые из SQLAlchemy URL, передают настоящий пароль в драйвер, а не маску `***`; пароль не выводится в логи. Ограничения на loopback и отдельную тестовую базу сохранены.
- Браузерные шаги учитывают закрытые панели, раздел доступа карточки, настройки переноса и уже открытую карточку. Жест повторного размещения выполняется на свободной части карты. Проверки серверных данных, точных координат и количества команд сохранены. При ошибке сохраняется снимок экрана.
- Сканер принимает только два проверенных бинарных шрифта с точными SHA-256. Изменённый шрифт отклоняется; добавлены регрессии. Проверки секретов и текстовых canary сохранены.

## Границы вывода

Это успешный локальный прогон текущего приложения с синтетическими данными. Подписи JWT проверяет настоящий backend через локальный fixture JWKS; Auth bootstrap и Storage заменены тестовыми реализациями. Настоящий Supabase Auth/Storage, реальная игровая сессия длительностью 20 минут, работа через интернет и production-развёртывание этим прогоном не подтверждены. Loopback smoke не является WAN SLO.

В `.github/workflows/ci.yml` push-триггер настроен только на `master`. Поэтому успешные локальные проверки `main` не означают успешный запуск GitHub CI для этой ветки; это проверяется отдельно по итоговому commit SHA. Настройки репозитория и триггеры в этом раунде не менялись.

[Windows/WSL2-инструкция](windows-setup.md) актуализирована по этим результатам. Windows, WSL2, Python 3.13/Node 22 и полный запуск с настоящим локальным Supabase на Windows здесь не проверялись.
